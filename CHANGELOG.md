# Changelog

## 2026-10-10

- **Quality suite: a `soak` check** (`quality/soak.py`). Three chats grow a turn a round on 5-6k-token histories, all at once beside a stream decoding a long reply, each turn resuming the previous one's kept state; every chat is then replayed alone as the reference. Every reply must equal its replay, every request succeed, at least half the turns actually resume, and the server answer afterwards. It is the pattern that broke CUDA graph relocation upstream (TensorFold #615), which no check here covered; the native v1.0.5 image passes it, 60/60 equal and 60/60 resumed (`evidence/2026-10-10-native-v1.0.5/soak/`). AGENTS.md now requires it, with drafts, concurrent and behaviour, before an engine change ships. Its first runs found one engine fault: a request sent twice in a row resumes but keeps no new state, so the next turn reads its history again (known issue; replies unaffected).
- **HumanEval's sandbox** runs in the image `recipe.toml` pins; it still named the removed Python image.
- **On TensorFold 1.0.5** (pin `8bea0406`, image `native-v1.0.5`): the port carried from 1.0.4 (`native-v1.0.5` on the fork). 1.0.5's greedy-only refusal (#582) covers the Metal engines only, so sampled requests are still served; its Nemotron prompt-state store stays out of Flash Next, which keeps its own; logprobs stay refused. Suite equal on every check (tools 60/60, JSON 30/30, IFEval 130/150, GSM8K 241, MGSM 219, MMLU 283, HumanEval 157, long context 55/55, vision 12/12); exactness at int8 and int4, the six cache-exhaustion cases and the capacity probe pass. One stream 76.9 / 125.9 / 99.3 / 128.0 tok/s, 16 users 297.2 / 510.9 / 387.7 / 518.4, the same as on 1.0.4 (`evidence/2026-10-10-native-v1.0.5/`).
- **The Python engine is removed; the recipe is native-only.** TensorFold froze its Python engine (`python-0.6`), and the native engine matches or beats it everywhere this recipe measures, so the recipe drops it: `docker/Dockerfile`, `docker/constraints.txt` and `flashnext-int4mixed-py0.6-ed78d6f.patch` are gone, and so are the `engine`, `tp`, `mtp_drafts` and `mtp_confidence` settings (`drafts = false` serves without drafts). The native settings take the plain names (`tensorfold_sha`, `patch`, `patch_sha256`, `image`); a `cluster.toml` or environment variable that still sets a removed or old name is refused with what replaced it. `cache_folder` names the existing folder under `tf_cache` (`ed78d6f...`), so caches stay valid and nothing downloads again. A local conversion (`converted_repo = ""`) now runs `spark/convert_mixed.py` in the engine's image (torch and safetensors are there). `up --src` (a Python source tree over the image's) is gone. Lost with it: logprobs, which the Python engine served at one rank only. Its measurements stay under `evidence/`.
- **Native: one stream 15-21% faster** (pin `ce40418a`): decode steps' CUDA graphs end at each cross-rank gather (the gathers run between graphs: 15 us instead of 25 inside one), and one captured step serves every sequence (at capture, the kernel arguments that point into the capturing sequence are noted and rewritten at launch for another; at most 96 plans) instead of each request capturing 40-odd graphs. One stream 77.1 / 125.7 / 99.1 / 125.7 tok/s fresh and 77.1 / 124.7 / 97.0 / 125.3 after other traffic (was 66.8 / 106.1 / 85.1 / 106.9); 4-16 users unchanged (16: 297.8 / 506.7 / 383.7 / 517.3). Bit-identical: the reply equals the Python engine's at int8 and int4, shared rounds and batched prompts equal alone, resume equals fresh, drafts 12/12, concurrent 12/12, behaviour, structured, sampled and URLs pass (`evidence/2026-10-10-native-v1.0.4-split-shared/`). `TENSORFOLD_FN_SPLIT_GRAPHS=0` / `TENSORFOLD_FN_SHARE_GRAPHS=0` (via `extra_env`) turn them off.
- **Native: one stream holds its speed on a long-running server** (pin `bc0402c1`). CUDA graphs were kept per sequence and only freed with the sequence, so pooled spares and kept prompt states piled them up (161 graphs over 9 sequences after the server checks against 18-73 fresh) and requests spent 140-365 ms recapturing; one stream fell 7-10%. A released sequence's graphs are now freed on both ranks. One stream: 66.8 / 106.1 / 85.1 / 106.9 tok/s fresh, 67.1 / 103.4 / 84.1 / 107.5 after the server checks (was 62-63 / 99-101 / 81-82 / 99-103); 16 users 296 / 506 / 381 / 502. Drafts 12/12, concurrent 12/12, behaviour, structured, sampled, resumed turns and URLs pass (`evidence/2026-10-10-native-v1.0.4-graphs/`).
- **The native engine is the default, on TensorFold 1.0.4** (`engine = "native"`, patch `tensorfold-native-v1.0.4.patch`, pin `fcf3092a`; `ENGINE=python` keeps the Python engine). Our Flash Next port carried from 1.0.2 to 1.0.4's release; 1.0.4 changes only `--slide` beside it. Suite on the 1M default equal to the Python engine's on every check (tools 60/60, JSON 30/30, IFEval 130/150, GSM8K 241, MGSM 219, MMLU 283, HumanEval 157, long context 55/55, vision 12/12; thinking off). Decode 69.1 / 110.0 / 88.7 / 112.5 tok/s at 1 user, 297.3 / 511.8 / 383.5 / 519.8 at 16 (Python: 68.7 / 109.0 / 89.0 / 109.9 and 299.5 / 475.2 / 372.0 / 542.0); first token at 16 users 0.41-0.55 s. `evidence/2026-10-10-native-v1.0.4/`.
- **Native: shared rounds in fewer launches.** DeltaNet, keeps and attention for every stream in one launch each (a 16-stream round had made about 4,100 launches), rounds up to 128 rows, prompts admitted together, sequences pooled instead of zeroed per request. 16 users: 260 / 412 / 311 / 429 to 297 / 512 / 384 / 520 tok/s; first token 0.8-1.0 s to 0.4-0.55 s. Kernel set: 217 variants (the multi-stream and int4 attention variants added).
- **Native: sampling, structured output, kept prompt states, HTTPS media URLs.** Sampling draws over both ranks' top-64 candidates (the full row when top-p or min-p reach past them; 20 of 20 sampled replies equal the Python engine's). `response_format` and `guided_*` through xgrammar 0.2.8 (libtfgrammar, built in the image), masks for every draft row, a grammar xgrammar refuses is a 400. A next turn resumes from the kept state one token before the last prompt's end (0.12 s to the first token against 2.1 s cold at 5.5k tokens; resumed equals fresh). `vision_urls` now defaults to true: public HTTPS image and video URLs, fetched as the Python server does.
- **Native: int4 KV** (`kv_dtype = "int4"`): 30% less cache a position, 0-10% lower throughput at 16 streams, scores within an item or two of int8, every exactness check equal to the Python engine's int4. int8 stays the default (`evidence/2026-10-09-kv-int4-ab/`).
- **Native: running out of cache memory no longer breaks the server.** Rank 0 had sent a round to rank 1 before growing its caches; a growth refused on rank 0 left the ranks' collectives out of step (an illegal address at int8, a hang at int4, a restart either way). Growth is now agreed by both ranks before the round; kept states and spares are freed first; a refused request ends alone. Six ~192k-token prompts at once: four answered, two refused cleanly, the server serves on.
- **Native: the verify timing flag and its counter set at engine creation** (they were whatever the allocator's memory held; events around every verify step when set).

## 2026-10-08

- **On TensorFold's newest Python engine** (patch pin `44e82a02`): TensorFold 1.0 is a native Zig engine that does not serve Flash Next on CUDA, so the recipe follows upstream's `python-0.6` branch to its tip, `ed78d6f` (ten commits past 0.6.6, among them this project's copy drafts #468 and two-rank image input #473, now dropped from the patch). Artifacts are named after it: image `tf-qwen38-int4mixed:py0.6-ed78d6f`, patch `flashnext-int4mixed-py0.6-ed78d6f.patch`. The startup warm-up of the ranks' point-to-point link moved into `cuda/comm.py` (`warm_exchange`), which fixes seven constructor tests it had broken; six two-rank tests updated for the admission's grammar field. Engine tests: 1,696 passed, upstream's own 2 failures unchanged. Shipped image: exactness 12/12, concurrency 12/12, vision 12/12, JSON-schema check 30/30; decode 69.3 / 107.6 / 88.3 / 110.4 tok/s at 1 user and 298.9 / 442.6 / 375.3 / 541.8 at 16; prompt passes 2,575 / 2,506 / 2,177 / 1,988 tok/s at 7k / 28k / 115k / 225k (2-5% under the 0.6.6 build's at the longer lengths, being checked). The converted checkpoint is hard-linked into the new engine's cache folder, so updating downloads nothing.

- **Structured output with `--parallel` on two ranks** (patch pin `5b45f8f9`): `response_format` (JSON object or schema) and `guided_*` (choice, regex, grammar) no longer return 400 under the concurrent profile. Rank 0 sends each admitted request's packed grammar with the admission, rank 1 compiles the same one, both mask their own vocabulary columns, and a constrained stream samples from its masked rows instead of the forward's pre-mask candidates (its first token too). Tested with 18 streams together, 8 schema-constrained, 1 regex, 9 free text: all valid; a malformed schema is a 400 and the server serves on. Shipped image: exactness 12/12, vision 12/12, JSON-schema check with grammars 30/30, rulers unchanged.

- **Both halves of the QSFP port as NCCL rails:** the cabled port is two PCIe x4 links and two RoCE devices; with the second addressed and both in `hca`, a 2,048-row prompt gather goes from 1.9 to 1.1 ms and prompt passes from 2,342 / 2,351 / 2,091 / 1,871 to 2,565 / 2,639 / 2,292 / 2,040 tok/s at 7k / 28k / 115k / 225k.
